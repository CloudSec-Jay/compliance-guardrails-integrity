00 / PREMISE

A control without evidence is an intention.
Evidence without a boundary is noise.

This project joins the two: state the risk, enforce a narrow rule, test both sides of it, and preserve only the record needed to support the result.

01 / CONTROL CHAIN

Requirement to record

  1. 01
    INTERPRET

    Define the risk.

    Translate a requirement into observable allowed and denied behavior.

    RISK
  2. 02
    ENFORCE

    Place the boundary.

    Use an SCP, permission boundary, admission rule, or release policy.

    RULE
  3. 03
    VERIFY

    Challenge the rule.

    Test positive, negative, failure, and rollback paths before expansion.

    TEST
  4. 04
    RECORD

    Preserve the result.

    Bind sanitized evidence to a commit, policy version, run, or digest.

    PROOF

02 / CONTROL LIBRARY

The review desk

A / AWS

Organization guardrails

SCPs and a developer permission boundary for logging, public access, root use, Regions, metadata, and escalation paths.

Review policies ↗ B / OPA

Admission policy

A Rego rule rejects privileged application and init containers, backed by positive and negative tests.

Inspect policy ↗ C / EVIDENCE

Control records

A sanitized evidence template and cautious NIST SP 800-53 map that keeps claims tied to actual artifacts.

Open ledger ↗ D / INTEGRITY

Release trust chain

Checksums, SBOMs, digest-bound signatures, attestations, identity verification, and explicit failure handling.

05 / LIMITS

No borrowed certainty.

Static validation does not prove a policy works in a target environment. A framework mapping does not create compliance. A signature proves origin, not safety. Gaps stay visible until deployment evidence closes them.
